# DatasetBuilder 개발 기록

## 2026-09-29 — 착수 및 랩 추출

- 목표: 원본을 보존하면서 유효 랩과 제외 근거를 재생성한다.
- 기존 Python 검증기의 `validate()` 결과에 있는 랩 경계를 재사용했다. 별도 경계 알고리즘을 만들지 않아 핫랩 카운터 유지·갱신 시차 처리가 달라지지 않게 했다.
- 시작 포함·끝 제외로 추출하고, 경계 샘플의 다음 랩 소유권을 자동 테스트 대상으로 추가했다.
- 설정 검사, 입력 SHA-256, 고유 출력 폴더, 미완료 manifest, 랩 CSV와 제외 범위를 구현했다.
- 관련 구현: [builder.py](../DatasetBuilder/builder.py). 검증 결과는 통합 검증 후 아래에 기록한다.

## 2026-09-29 — 품질 보고 및 데이터 분리

- 외부 의존성 없이 열 수 있는 SVG 포함 HTML을 구현했다. 시각화 축소는 구간별 양 축 극값을 보존하고 CSV는 축소하지 않는다.
- 시간순 70% / 15% / 나머지 분리와 최소 집합 크기를 구현했다. 3랩 미만은 분리 미완료로 표시한다.
- 샘플 간격은 이전 랩의 첫 간격을 제외하고 종료 경계까지 포함한다. 페이지 변경 간격은 호스트가 관측한 값이며 게임 내부 지연으로 표현하지 않는다.
- 관련 구현: [report.py](../DatasetBuilder/report.py), [테스트](../DatasetBuilder/test_builder.py).
- 다음 작업: 자동 테스트, 실제 15랩과 대조, 반복 생성과 보고서 검사.

## 2026-09-29 — 재사용 주행 검토 기능 착수

- `review scan`과 `review finalize`를 분리했다. 검사 결과와 명시적 판정을 서로 다른 폴더에 보존하며 기존 데이터셋을 변경하지 않는다.
- 진행률별 대표값과 median/MAD 기준은 train 랩에서만 계산한다. train 검사에는 자기 자신을 제외한다. 후보 탐지 임계값은 승인된 계획대로 TOML에 고정했다.
- 데이터셋은 원본 검증 및 행 단위 재대조, 제외 범위·분리 목록 확인을 통과해야 한다. 검사 입력과 결과 해시를 저장하고 확정 시 다시 확인한다.
- 판정 초안은 모든 랩을 미검토로 생성한다. 불명확한 후보 또는 비교 자료 부족이 있는 랩을 사용 가능으로 확정하지 못하도록 검사한다.
- 관련 코드: [검토 실행](../DatasetBuilder/review.py), [후보 탐지](../DatasetBuilder/review_analysis.py), [검토 보고서](../DatasetBuilder/review_report.py).
- 아직 검증하지 않은 상태이며 자동 테스트 및 실제 11랩 적용 결과는 후속 기록에 남긴다.

## 2026-09-29 — 후보 탐지와 검토 보고 구현

- [review_analysis.py](../DatasetBuilder/review_analysis.py)에 랩별 진행률 구간 중앙값, train 기준 중앙값/MAD,
  자신을 제외한 train 검사, 여섯 종류 후보와 비교 자료 부족 표시를 구현했다.
- 랩별 대표값을 먼저 계산해 샘플 수의 가중을 없앴다. validation/test의 값은 기준 계산에 전달하지 않는다.
  출발선 wrap 및 랩/segment 경계를 넘는 창은 비교하지 않는다. 실제 호스트 시각으로 지속 시간과 병합 간격을 계산한다.
- 후보가 있어도 자동 제외하지 않는다. 정상적인 패드 조향 보정도 통계적 후보가 될 수 있으므로 사람의 원래
  주행 의도·접촉 여부로 바꾸어 해석하지 않는다. 불충분한 비교 자료는 사용 가능 확정을 막는다.

- 후속으로 train/validation/test 모두 사용 가능인 판정의 집합 보존과 검사 결과 변조 검증을 추가했다.

- 남은 작업: 실제 11랩의 근거 있는 판정, 확정 목록 재생성과 저장 실패 처리 검증.

  경로 적합성을 해소하지 못했다. 이 두 랩을 보류했으며 접촉·사고·도로 이탈 원인을 단정하지 않았다.
