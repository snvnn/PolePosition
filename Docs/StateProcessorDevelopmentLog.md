# StateProcessor 개발 기록

## 2026-09-29 · 착수

- 목적: 검증된 기준 주행선에 대한 차량 상태를 같은 Rust 코어로 기록 재생과 ACC 실시간 진단에서 계산한다.
- 입력: [TrackModel](../track_models/track-1790677262927433400-796fb617/manifest.json), [확정 검토](../reviews/final-1790674957929734700-befda832/manifest.json). 학습 5랩만 방향각 검증에 사용한다.
- 기존 `poleposition-recorder::session::Tracker`가 이미 공개 라이브러리여서 구간 판정 코드를 복제하지 않고 재사용하기로 했다.
- 계획 조사에서 얻은 방향각 변환과 처리 시간은 구현 검증으로 간주하지 않는다. 아래에 실제 수행 결과를 추가한다.
- 착수 시 미완료: 입력 준비, 코어, 기록 재생, 실게임 검증, 규약과 체크리스트 갱신. 아래 기록은 이후 실제 수행 결과다.

## 2026-09-29 · 입력 준비와 방향각

- [prepare.py](../StateProcessor/prepare.py)에서 기존 TrackModel 로더와 확정 검토 검사를 재사용했다. 기준 경로와 검토 결과의 연결, 원본·판정·분리·경로를 포함한 입력 31개 해시를 확인했다.
- 후보 선택에 사용 가능한 train 1·3·4·5·9번만 사용했다. validation/test와 보류 랩은 준비 목록에 남기되 방향각 계산에서 제외했다.
- 실제 monotonic 시간으로 ±100ms 창과 200ms 중심 간격을 선택했다. 계획 조사에서 행 간격으로 얻은 수치는 최종 결과로 사용하지 않았다.
- 1,640창: 랩별 327 / 335 / 326 / 325 / 327개. `wrap(heading + π/2)`가 선택됐다. 절대 이동 방향 오차 중앙값 **0.450439도**, p95 **2.996461도**. 차순위 중앙값 **55.598835도**, 차이 **55.148396도**. 기본 기준을 통과했고 변경하지 않았다.
- [준비 manifest](../state_runs/prepared-1790679300781499500-3e604d8c/manifest.json), [방향각 프로필](../state_runs/prepared-1790679300781499500-3e604d8c/heading_profile.json), [반복 준비](../state_runs/prepared-1790680268489578900-3e536956/manifest.json).
- 두 준비 실행의 config.json·heading_profile.json·replay.json은 바이트가 같았다. 시간·출력 ID만 예외다.
- 초기 sha2 다운로드는 제한된 네트워크에서 실패했다. 허용된 의존성 다운로드로 진행했으며, 최초 `--locked`는 새 의존성의 lock 갱신을 막아 실패했다. 정상 fetch로 버전을 기록한 후 offline 빌드가 통과했다.
- 다음 작업은 같은 프로필을 사용하는 Rust 계산 코어와 기록 재생이었다.

## 2026-09-29 · 투영과 상태 처리

- [Rust 로더](../StateProcessor/src/model.rs)는 준비/경로 해시·필수 입력 목록·스키마·좌표 규약·기하 유효성을 검사한다. 프로필의 변환이 선택 후보와 일치하는지도 검사한다.
- [계산 코어](../StateProcessor/src/processor.rs)는 전체 폐곡선 투영, 보간 접선·곡률, 부호 있는 횡오차와 방향 오차, 출발선과 후진의 누적 거리를 구현한다. 전역 탐색 비용이 실측 목표를 충족해 첫 버전에서는 공간 검색 인덱스를 추가하지 않았다.
- 획득 후보 3회 확인, 패킷 중복, 100ms 만료, 가까운 병렬 구간의 모호성, 물리적 위치 도약·전역 후보 충돌과 재획득을 명시적으로 구분했다. 오래된 값이나 잘못된 상태에는 투영값을 남기지 않는다.
- 라이브 구간 구분은 기존 `poleposition-recorder::session::Tracker`를 호출한다. 기존 기록기의 코드나 구간 규칙은 변경하지 않았다. 정상 핫랩 랩 증가·타이머 갱신 시차의 기존 회귀 테스트도 유지했다.
- [코어 합성 테스트](../StateProcessor/tests/core.rs) **26개** 통과: 직선·원·역방향, 곡률 순환 보간, wrap·후진, 정지, 중복, 페이지/관측 만료, 시간 역전, 점프, 비유한 값, identity 불일치, invalid lap, reset, 세션/카운터, 평행 구간과 전역 후보 충돌, non-live 관측.
- [저장기 테스트](../StateProcessor/src/writer.rs) **3개** 통과: 제한 큐 포화 집계, 종료 시 200이벤트 배출·기존 파일 보호, 주입한 저장 오류의 전파. 실제 디스크 고장을 유발한 테스트는 아니다.
- 구현 도중 Rust 차용 충돌·추론 불가능한 숫자형·잘못된 소수 리터럴로 컴파일이 실패했다. 타입/소유권/리터럴을 수정한 뒤 테스트를 실행했다. 초기 clippy의 중첩 조건·불필요한 unwrap·테스트 모듈 위치 지적도 수정했고 최종 `-D warnings`가 통과했다. 실패 시점은 통과 실적으로 계산하지 않았다.
- 다음 작업은 실제 전체 세션 재생, 입력 불변성과 출력 재현성 검증이었다.

## 2026-09-29 · 실게임 검증

- 사용자가 정지·직선/코너 주행·출발선·일시정지/재개·게임 종료/재실행을 직접 수행했다. StateProcessor는 읽기 전용이며 차량 조작을 보내지 않았다. 기존 DrivingRecorder를 다시 켜지 않았다.
- **360초 진단**: [실게임 결과](../state_runs/live-1790679556195446900-16272/manifest.json), [보고서](../state_runs/live-1790679556195446900-16272/report.html), [이벤트](../state_runs/live-1790679556195446900-16272/events.csv), [요약](../state_runs/live-1790679556195446900-16272/summary.json).
- 관측 **15,854개**, 상태 행 **15,866개**, ready **15,846개**, acquiring **8개**, unavailable **12개**, invalid **0개**. 상태/이벤트 누락 모두 0. 제한 시간 정상 종료 후 큐 배출 및 파일 재읽기 통과.
- 속도 1km/h 미만인 ready 관측 2,847개로 정지 상태 확인. 주행 중 출발선 2회 통과(25.600초 / 118.270초)에서 epoch가 유지됐다. 경계의 누적 거리 증분은 각각 0.791m / 0.938m로 연속이었다.
- 일시정지 25.650→재개 29.700초, 일시정지 129.590→재개 135.650초 확인. paused에서는 투영 필드가 비어 있고 재개 후 3개 새 관측에서 ready로 복귀했다.
- 종료 후 off 159.091초 → disconnected 162.120초 → 재실행 live 281.080초 → 새 epoch에서 ready 281.110초 확인. 차량·트랙·공유 메모리 식별값이 프로필과 일치했다.
- 표시와 저장이 켜진 실측:

- 코어 p99 목표 통과. 목표 폴링 슬롯 1회 지연을 집계했다. 기록 큐 누락과 구분하며, 실시간 시험 중 자동 테스트 등 다른 작업도 실행됐으므로 전용 환경의 최악 지연 보장으로 해석하지 않는다. 공유 메모리에 도달하기 전 게임 내부 지연은 측정하지 않았다.
- 게임이 종료된 상태에서 **추가 5초 진단**을 실행해 처음부터 disconnected인 경우도 확인했다: [미실행 결과](../state_runs/live-1790680317794416600-5632/summary.json). 관측 0개, 정상 종료, 누락 0. 표본이 없을 때 코어 p99 통과를 true로 표시하지 않도록 `null`로 구분했다.
- 실제 ACC 리플레이 모드 전환·의도적인 페이지 동결·Ctrl+C 입력 종료는 별도 실게임 동작으로 수행하지 않았다. 관련 상태 reset/만료와 큐 배출은 자동 테스트로 검증했다. 리플레이 화면을 본 적이 있다는 근거로 기록하지 않는다.
