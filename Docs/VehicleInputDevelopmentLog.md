## 2026-09-29 — 명령·감시 프로세스·중단

- 실제 변경: 별도 자식 명령 생성 프로세스, 양방향 로컬 파이프, 양쪽 최신값 슬롯, QPC 공통 시각, F7/F8 전역 키 등록, 자체 텔레메트리/StateProcessor 계산을 연결했다. 최신 관측 출처도 대조한다.
- 결정: vJoy 소유권은 감시자 하나에만 있다. 자식의 상태 보고를 신뢰해 제동을 결정하지 않는다. 가속/제동 동시 요청과 제동 잔여량에는 가속 0을 우선한다. 중단은 전체 브레이크를 즉시 요청하고 자동 재출발을 금지한다.
- 실제 변경: 관측/페이지/명령 100ms, 전면·속도·추적·세션·로그·자식 종료 조건을 적용했다. 새 관측 0.5초 정지 확인과 게임 중단 확인을 별개로 기록한다. 확인이 안 되면 제동 상태를 유지한다.
- 최종 점검 보완: F7로 시작하기 전 생성자 종료 등이 발생한 경우에는 비중립 제동을 내보내지 않고 중립 반환하도록 구분했다. 시작 전 출력 차단 회귀 검사를 추가하고 전체 Rust 74개를 다시 통과했다.
- 발견/해결: 만료된 명령의 늦은 검출 시각을 기준으로 지연을 재면 결과가 낙관적으로 보일 수 있다. 최초 만료 기한을 중단 측정 시작에 반영하며 늦은 거절/중지 이벤트가 이미 지난 만료를 가리지 않게 했다. F8/Ctrl+C 시각은 수신 스레드에서 기록한다.
- 검사: 실제 자식을 `kill`한 경우, Windows `NtSuspendProcess`로 이 시험이 생성한 자식만 정지한 경우, 파이프 단절에도 감시 코어가 중단을 내보냈다. 그 출력 대상은 **모의 장치**다. DLL/ACC 반영을 확인한 시험은 아니다.
- 제한: 감시자 자체 강제 종료·드라이버 장애는 제동 보장을 제공하지 않는다. 실제 마지막 입력 유지/리셋 동작을 확인하기 전 전체 완료로 처리하지 않는다.

## 2026-09-29 — 재부팅 확인·중립 전송·DLL 초기화 오류 수정

- 사용자 재부팅 완료 회신을 받았고 OS 마지막 부팅 시각 **2026-09-29 21:45:23 KST**를 확인했다. 장치 1 Free, 드라이버/SDK 버전 일치, Windows PnP 정상 인식은 [재부팅 후 조회](../input_profiles/post-reboot-1790686232063.json)에 남겼다.
- 초기 조회는 X/Y/Z 모두 32767(Windows 범위 0~65535)이었다. 공식 [드라이버 초기화 구현](https://github.com/BrunnerInnovation/vJoy/blob/v2.2.2.0/driver/sys/hid.c)을 확인하고 [초기값 설정 스크립트](../VirtualJoyStick/SetNeutralDefaults.ps1)를 추가했다. ACC와 입력 프로세스가 없고 vJoy 장치가 1개인 경우에만 실행하며, 관리자 권한으로 Device00/Device01의 Y/Z 초기값을 0%로 저장한다. X와 장치 축 구성은 변경하지 않는다. Device00은 기본 장치 초기화용 공통값이므로 다른 vJoy 장치가 있으면 실행하지 않는다.
- 실제 관리자 실행: [변경 전 값·복원 파일·결과](../input_profiles/neutral-defaults-1790686246499-57ee4b6f/result.json). 값 저장과 vJoy 장치 재활성화는 성공했지만, 새 WinMM 조회는 계속 중간값을 반환해 **초기값 관측 검증 실패**로 보존했다. 레지스트리 저장 성공을 초기 페달 해제 검증 성공으로 바꾸지 않았다. 복원용 `restore-defaults.reg`는 이 실행에서 변경한 네 값만 되돌린다.
- 실제 검사에서 `Call to RegisterClassEx failed!` / `Creation of dummy window failed!` 팝업이 발생했다. 새로 작성한 검사 예제가 DLL을 해제한 뒤 같은 프로세스에서 다시 로드한 것이 원인이었다. 해당 검사 프로세스를 종료했고 최초 실행은 결과 저장 전 중단되어 유효한 검증 근거로 쓰지 않는다.
- 수정: [중립 검사 예제](../VirtualJoyStick/examples/neutral_check.rs)는 SDK 인스턴스를 재사용한다. [Native 로더](../VirtualJoyStick/src/native.rs)도 프로세스당 최초 로드만 허용하고 추가 로드를 명시적으로 거절하여 같은 SDK 팝업 경로를 차단한다. [공식 SDK 내부 창 등록 코드](https://github.com/BrunnerInnovation/vJoy/blob/v2.2.2.0/apps/common/vJoyInterface/vJoyInterface.cpp)와 대조했다.
- 실제 장치 확인: ACC 종료 상태에서 장치 확보 → 조향 중앙·페달 해제 `[16384,0,0]` 전송 → 반환이 성공했다. 이미 열린 Windows 관측에서는 `[32767,0,0]`이었다. ## 2026-09-29 — 패드 유선 입력 복원 검증 실패

- 사용자가 재실행 후 입력 없음, 이후 `유선 연결은 입력이 안되고, 블루투스 입력을 받음`을 회신했다. 원본 파일 복원 성공과 실제 유선 패드 복원 성공을 분리하며, 해당 체크리스트는 미완료로 유지한다.

- 읽기 전용 XInput 네 슬롯은 모두 1167을 반환했다. 제한된 실행 환경의 영향인지 확인하기 위해 별도 승인된 일반 환경의 System32 DLL로 재조회했으나 같았다. 장치 열거 성공만으로 입력 경로 정상이라고 판단하지 않으며, 이 관측만으로 vJoy가 원인이라고 단정하지 않는다. 관련 서비스·드라이버를 임의로 교체하거나 제거하지 않았다.
- 블루투스 연결을 끊고 다른 USB 포트/데이터 케이블에서 비교하도록 요청했다. 원래 지정한 유선 조건의 패드 반응 확인이 남아 있으며 5단계 전체 완료를 선언하지 않는다.
- 다른 포트 확인 후에도 사용자는 유선 입력 없음으로 회신했다. [진단 스냅샷](../input_profiles/xbox-wired-diagnostic-1790690567497232000.json)을 보존했다. 이후 조회 시 USB 장치는 `CM_PROB_PHANTOM`(현재 연결되지 않은 장치)이었고 관련 드라이버도 중지 상태였으므로, 이를 연결 중 드라이버 실패로 단정하지 않았다. 재연결 상태 유지 확인을 요청했다.
- 다음 복구 후보는 해당 USB 인스턴스 하나의 장치 재시작이다. [Microsoft PnPUtil 규약](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax#restart-device)을 확인했으며 제거·드라이버 교체·재부팅은 예정하지 않았다. 아직 이 장치 재시작은 실행하지 않았다.
- 사용자 유선 연결 유지 회신 후 해당 USB 인스턴스가 Present=true·문제 코드 0인지 확인했다. 관리자 권한으로 그 Xbox USB 장치 하나에만 PnPUtil 재시작을 요청했다. [실행 스크립트](../input_profiles/xbox-usb-restart-20260929/restart.ps1)와 [결과](../input_profiles/xbox-usb-restart-20260929/result.json)를 보존했다.
- 실제 결과: 종료 코드 **3010**, `구성 작업을 완료하려면 시스템을 다시 부팅해야 합니다!`. 장치 목록 상태는 OK였지만 XInput 네 슬롯은 여전히 1167이다. 장치 재시작·유선 입력 복구를 통과로 기록하지 않는다. `/reboot` 옵션 없이 실행했으며 실제 PC 재부팅, 드라이버 제거/교체, 추가 ACC 설정 수정은 하지 않았다.
