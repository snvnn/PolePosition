# 강화학습 실행 규약 — 개발 중

2026-10-03. [원래 계획](TrainingControllerPlan.md)의 명시된 제한을 코드로 옮겼다.
현재 구성은 초기화 검증·회차 실행 제어·Gymnasium 경계·SAC 체크포인트·교사 행동 재연결·Rust v2 평균 정책 추론이다.
**Rust v2 직접 제어·경험 저장·정지 후 SAC 갱신·체크포인트 재개를 Python GUI에 연결하고 실게임 60초 회차 두 번으로 검증했다. 자동 메뉴 초기화와 실제 완주 성능 평가는 별도 후속 과제다.**
모의 포트에서 통과한 검사를 실제 ACC 검증 또는 주행 성능으로 해석하지 않는다.

## 환경

- `.venv-controller`: Python 3.11, PyTorch 2.8.0+cpu, NumPy 2.3.3, Stable-Baselines3 2.7.0, Gymnasium 1.2.0.
- 직접 의존성: `TrainingEnvironment/requirements.txt`.
- 실제 설치한 전체 버전 잠금: `TrainingEnvironment/requirements.lock.txt`. `pip check` 통과.
- 기존 `.venv-training`은 변경하지 않았다. 새 환경은 기존 환경을 공유하지 않는 별도 venv다.
- `TrainingEnvironment/config.toml`에는 계획서에 수치가 명시된 값만 기록했다.

## 자동 초기화

`ResetEngine`은 등록된 화면·동작을 제공하는 `ResetPort`를 사용한다.
각 동작 전에 지정 화면과 ACC 전면 여부를 확인하고 동작 후 다음 화면을 기다린다.
고정 시간 대기만으로 다음 클릭을 실행하는 코드는 없다.

마지막 주행 화면을 확인한 뒤 입력 이후 시각의 새 텔레메트리를 요구한다.
BMW M4 GT3 / Brands Hatch / 핫랩, 출발 위치·방향·정차 조건을 모두 통과한 뒤
추적·특징·랩 이력을 초기화한다. 실패하면 같은 엔진에서 다음 초기화를 시도하지 않는다.
`verify_three`는 주행·학습 콜백 없이 3회 연속 검증한다.

`ResetSpec`의 화면 이름, 동작 이름, 위치·방향·정차 허용값, 초기화 제한 시간은 필수 입력이다.
계획에 없는 기본값을 채우지 않았다. 테스트의 작은 허용값은 합성 검사용이며 실제 프로필이 아니다.
화면 캡처/등록/인식과 실제 메뉴 조작을 담당하는 Windows 포트는 아직 연결하지 않았다.

## 반복 실행

`BatchRunner`는 초기화 → 출발 준비 → 고정 정책 수집 → 정지 확인 → 경험 검증 →
학습·저장 순서로 `BatchPort`를 실행한다.

- 최대 10회 또는 7200초 중 먼저 도달한 조건으로 종료한다. 초기화·학습 시간도 전체 시간에 포함한다.
- 수집 회차에 기본 1800초 마감 시각을 전달한다. 네이티브 포트가 이 시각과 중지 검사를 준수해야 한다.
- 한 묶음의 속도 단계는 고정된다. 선택할 수 있는 단계는 계획서의 10·20·40·80·120·160·200·240km/h다.
  3랩 조건의 계산은 구현했지만 실제 로그 증거를 검증하는 단계 해제 연결은 아직 없어 GUI에서는 이 실행부를 활성화하지 않는다.
- 정지 확인 전에는 경험을 반영하거나 정책을 갱신하지 않는다.
- 갱신은 검증된 새 전이 수의 1/4(내림), 회차당 최대 2000회다.
- 주행 전후 정책 식별자가 달라지면 실패한다. 실제 포트는 주행 중 고정 Rust 정책을 사용해야 한다.
- 평가에는 deterministic 수집을 요청하며 경험 반영·가중치 갱신·학습 체크포인트 저장을 하지 않는다.
- 취소·통신/저장/정지 오류 뒤에는 다음 회차를 시작하지 않는다. 종료된 runner는 다시 실행할 수 없다.
- 시간 제한 도달 뒤에도 정상 정지 확인은 수행한다. 저장하지 못한 부분 갱신을 완료 체크포인트로 표시하지 않는다.

## Gymnasium 경계

`LiveEnvironment`는 명시적으로 제공된 v2 특징 목록만 사용한다. 기존 v1 19개 특징을 수정하거나
새 정책의 입력으로 자동 변환하지 않는다. 행동은 정규화된 두 값이며 실제 vJoy 소유는 Rust 포트에 남긴다.

50Hz 행동 요청과 함께 원본 관측 순번을 전달한다. 반환된 다음 관측은 다음 조건을 만족해야 한다.

- 원본 순번 일치, 다음 순번 증가, 동일 추적 epoch.
- 원본 관측 시각 ≤ 행동 전송 시각 < 다음 관측 시각.
- 명시된 특징 개수와 유한한 특징·보상.
- 과제 종료(`terminated`)와 외부 시간 제한(`truncated`) 구분.

다음 관측이 없거나 시스템 오류가 생기면 `TransitionUnavailable`로 중지한다.
이 경우 호출자는 replay에 전이를 넣을 수 없다. 이전 관측으로 가짜 다음 관측을 채우지 않는다.
보상 수식과 계수는 네이티브 포트/설정 연결의 미정 과제로 남아 있다.

## 체크포인트

`save_checkpoint`는 정지 확인 콜백과 비어 있지 않은 입력 해시 목록을 요구한다.
SAC의 128×128 은닉층, 두 critic, 배치 256, 학습률 0.0003, 버퍼 200000, seed 42, CPU를 검사한다.
각 저장은 새 폴더에 다음 자료를 만든다.

- `model.zip`: 라이브러리가 저장하는 정책·critic·actor/critic/entropy optimizer.
- `replay.pkl`: 라이브러리 replay buffer.
- `rng.pt`: Python·NumPy·PyTorch 난수 상태.
- `environment_rng.json`: Gym 환경 및 행동/관측 공간 난수 상태.
- `manifest.json`: 입력·출력 해시, 환경 버전, 속도 단계, 누적 회차, 완성 여부.

복원은 완성 여부와 파일/입력 해시를 확인한 뒤 수행한다. 로더는 이 프로그램에서 생성한
로컬 체크포인트용이며 외부의 임의 pickle을 가져오는 기능이 아니다.
복원 후 실제 주행은 새 초기화가 필요하다. 실게임 자체의 완전 재현성을 보장하지 않는다.
오프라인 초기 정책 생성은 `pretrain.toml`에 gamma=0.99, tau=0.005, entropy/target entropy=auto를 명시한다.
이는 고정 SB3 2.7.0의 기본값을 출발값으로 채택한 것이며 실제 주행에 대한 튜닝/검증값이 아니다.

합성 초기화·반복 실행 15개, Gym 관측/행동 경계 5개, 실제 SB3 체크포인트 3개가 통과했다.
체크포인트는 복원 뒤 다음 학습 갱신의 모든 정책 텐서가 연속 갱신과 동일함을 확인했고,

[Gymnasium 시간 제한 규약](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/).

## 교사 행동 재연결과 v2 평균 정책

`.venv-controller/Scripts/python.exe -m TrainingEnvironment prepare-teacher --sources ModelTrainer/sources.toml`.

기존 검증된 실제 PID 기록의 관측 순번·추적 epoch·명령 순번으로 요청과 첫 성공 전송을 연결한다.
기존 정지·저장·원본 해시 검증을 그대로 통과해야 한다. 조향도 중복 모호성 검사에 포함한다.
요청값과 전송값은 별도로 보존하고, 전송이 없는 요청은 제외한다.
`steering_raw`는 출력 자료에서 제외한다. 행동은 `[requested_steering, requested_throttle-requested_brake]`이며
겹치는 페달은 거절한다. 새 두 행동의 정규화는 실제 축 범위를 유지하며 기존 v1의 0.20/0.60 배율을 적용하지 않는다.
실제 장치의 제한·변화율은 별도 Rust 감시 규약으로 계속 제한되어야 한다.

원래 run별 train/validation/test 배정과 준비 경로를 유지한다. Windows 일반 경로와 `\\?\` 경로가
같은 폴더를 가리키는 경우에도 파일 동일성으로 중복을 거절한다.
이 산출물은 행동과 원 관측을 다시 연결한 자료다. 50Hz 특징 재표본화·v2 정규화·사전학습을 완료한 자료는 아니다.
따라서 `complete: true`와 별개로 `policy_training_ready: false`를 기록한다.

`policy.export_candidate`는 명시된 특징명·평균·표준편차와 SAC actor 평균 네트워크를
별도 `schema_version: 2` JSON으로 내보낸다. Rust `poleposition-policy predict-v2-candidate`가
동일 정규화 → 128 ReLU → 128 ReLU → 두 tanh 출력을 계산한다. 기존 v1 형식과 로더는 유지한다.
합성 입력 128개에서 실제 Python/Rust 두 출력 오차가 기존 수치 대조 기준 1e-5 이내임을 검사했다.
수치 대조가 통과한 후보도 `eligible_for_live: false`다. 특징 규약 확정이나 실게임 통과를 대신하지 않는다.

## 완주 평가 계산

`DrivingRecorder.laps.FinishLineTracker`는 기존 기록 검증기의 출발선 판정을 공유한다.
랩 카운터 증가와 핫랩 타이머 초기화 판정, 기존 5초 중복 방지 조건을 그대로 유지한다.
두 출발선 사이만 완주로 계산하며 segment를 가로지르지 않는다. 출발선 행의 게임 유효성은 다음 랩에 속한다.

`TrainingEnvironment.evaluation.LapEvaluation`은 검증된 관측과 실제 전송 구간의 모델 식별자·축별
제어 주체를 받아 판정한다. 첫 출발선 이전 구간부터 모델이 조향과 페달 모두를 제어해야 한다.
제어 증거 누락·구간 미포함·정책 변경·연속성 실패·게임 랩 무효·탐색·학습·replay 유입은
사유로 보존하고 해당 랩을 통과로 세지 않는다. 마지막 불완전 랩은 완주에 포함하지 않는다.

`next_stage_candidate`는 동일 모델 SHA-256과 현재 상한의 유효 3랩으로 다음 한 단계만 계산한다.
같은 원본·시간 구간은 중복 집계하지 않고 겹친 구간은 거절한다. 240km/h 다음 단계는 없다.
이는 계산 인터페이스이며 승인 파일 로더나 실제 단계 해제가 아니다. 원본 해시 검증,
Rust 감시기의 연속성·전송 증거 연결, 결과 저장·보고서와 GUI 연결은 미완료다.
합성 입력을 실제 주행 증거나 고속 배포 허가로 사용하지 않는다.

## GUI 기반 v2 자료 준비와 사전학습 — 2026-10-03

기존 `TrainingController` 창의 작업 선택에서 다음 순서로 실행한다.

1. **강화학습 자료 준비**: 설정은 `ModelTrainer/sources.toml`. 기존 교사 요청/전송을 검증하고 새 자료 폴더를 만든다.
2. **강화학습 사전학습**: 준비가 완료되면 학습 데이터 경로가 자동 입력된다. 설정은 `TrainingEnvironment/pretrain.toml`.
3. **중지 / 이어서 학습**: 마지막 완료 epoch의 `last.pt`를 선택해 새 결과 폴더에서 재개한다. 최근 결과의 체크포인트 선택도 사전학습 작업으로 전환한다.

실제 작업은 별도 `.venv-controller` 자식 프로세스에서 실행한다. 기존 GUI의 단일 작업·생존 신호·중지·창 종료 규약을 사용한다. Windows 한글 관리 메시지도 UTF-8로 고정한다. 실제 자동 주행 학습 항목은 미연결 상태를 명시한다.

### 특징과 데이터

- Rust `features_v2::FeaturesV2`가 기존 19개 특징 계산을 재사용하되 별도 35개 특징 버전을 만든다. 기존 v1 모델 규약은 그대로다.
- 추가값: 관측 **이전** 성공 전송의 조향/가속/브레이크, 기어, 속도/횡오차/방향오차 변화율, 160·320m 곡률, 0·10·20·40·80·160·320m 목표 속도.
- 이전 입력은 동일 tracking epoch이며 관측보다 엄격히 과거이고 100ms 미만이어야 한다. 해당 관측에 대한 미래 교사 정답 전송값을 입력으로 사용하지 않는다.
- 기존 인과적 이력·100ms 공백 초기화를 공유한다. 완성된 특징을 최소 20ms 간격으로 선택하며 미래 보간이나 가짜 50Hz 관측을 만들지 않는다. 실제 불규칙 수집 주기 때문에 자료 행수/시간은 정확히 50Hz가 아니다.
- 사람의 검토 통과 train 5랩만 속도 기준 계산에 쓴다. XZ 최근접 기준 경로점에 속도를 배정하고 각 랩의 중앙값/주기 보간 후 랩 간 중앙값을 취한다. 공간 최근접 속도 기준은 오프라인 초기 기준이며 고속 제어 성능을 보증하지 않는다.
- 교사의 출발 가속 목표와 해당 실행의 속도 상한은 별도로 보존한다. 전방 속도 기준에는 상한을 적용한다.
- 정규화 평균/표준편차는 교사 train만 사용한다. validation/test와 원래 run 배정을 유지한다.

### 학습과 저장

- SAC의 128×128 평균 행동 분기만 두 행동 MSE로 사전학습한다. critic·target critic은 변경하지 않고 replay는 비워 둔다.
- 구현 기본값: Adam 0.0003, 배치 256, 최대 100 epoch, validation 개선 없음 10 epoch에서 중단, seed 42, CPU 1스레드. TOML에 명시한다.
- 최저 validation MSE의 모델을 선택한 뒤 test를 한 번 평가한다. test로 조기 종료나 모델 선택을 하지 않는다.
- `last.pt`는 마지막 완료 epoch의 정책, 사전학습 optimizer, 순서 난수 상태, 최선 정책과 학습 기록이다. 중간 미완료 epoch는 재개 지점으로 표시하지 않는다. 초기 정책 `model.zip`과 정규화는 완료 결과에 별도 저장한다.
- 입력/출력 해시를 검증한 로컬 산출물만 재개한다. 이 체크포인트는 실제 강화학습의 replay 포함 체크포인트와 별도 종류다.
- 완료 시 Rust 후보를 내보내고 validation의 128개 관측으로 수치 대조한다. `eligible_for_live=false`를 유지한다.

## 랩 경계 온라인 SAC 연결 (2026-10-03)

GUI `강화학습`은 `verify5 → verify10 → verify30 → train` 순서로 실행한다. 검증은 같은 초기 정책·경로·보정·제어 설정의 실제 직접 제어 결과만 인정한다. PID 비교 주행은 통과 근거가 아니다. `이전 통과 주행 결과`에는 직전 `sac-session-*` 폴더를, 온라인 재개에는 `sac-checkpoint-*` 폴더를 선택한다.

- `online.toml`은 첫 배치 1회차, 회차 1800초, 목표 10km/h다. 전체 제한은 GUI에서 최대 7200초, 배치는 최대 10회차다. `online-first-cycle.toml`은 연결 검증을 위한 60초 제한이며 완주 평가가 아니다.
- Rust supervisor가 배치 전체의 F7/F8을 소유한다. 파일 요청은 다음 회차를 준비할 뿐 시작 입력을 만들지 않는다. 정지·해제 후 수동 출발 준비와 새로운 F7이 필요하다. 학습 중 F7은 버린다.
- 출발·특징 이력·목표 속도 준비까지 PID를 사용하고, 속도 8~12km/h가 1초 유지되면 v2 정책이 조향과 부호 있는 가감속 모두를 결정한다. 평균·분산 네트워크는 회차 동안 고정한다. 직접 제어에서는 네이티브 guardian 안에서 작은 고정 크기 네트워크를 계산하여 입력과 경험의 별도 IPC 유실을 없앴다. 추론 10ms 초과는 중단하며, 실제 소요 시간과 guardian 주기를 기록한다.
- 관측은 기존 35개 특징, 목표 10km/h, 고정 정규화를 사용한다. 20ms 절대 시각 예약으로 결정하고 늦은 관측을 복제하거나 밀린 명령을 몰아서 내보내지 않는다. 기록은 기존 bounded Sink의 비차단 큐를 쓰며 하나라도 빠지면 학습을 거부한다.
- 최초 bootstrap은 사전학습 평균·critic을 가져오고 미학습 log_std의 가중치를 0, bias를 -4로 초기화한다. 학습과 추론 모두 log_std를 [-5,-2]로 제한한다. xorshift64* + Box-Muller 난수 상태를 보존하며 같은 epsilon을 주어 Python/Rust 결정론·확률적 행동을 128개 실제 관측에서 대조한다.
- 시간 순서가 `source observation ≤ first successful apply < next observation`인 경험만 구성한다. replay에는 정책이 선택한 두 행동, 별도 로그에는 제한된 요청과 실제 축을 기록한다. 준비·정지 제어는 제외하며 실제 마지막 관측이 없으면 회차 자동 학습을 거부한다.
- 보상은 `Δs - .1Δt - .2 lateral²Δt - .1 heading²Δt - .01 ||Δapplied||² + terminal`이다. 유효 완주 +10, 이탈·무효 랩·10초 순전진 0.5m 미만 -10, 시간 초과는 추가 보상 0이다. 후진은 음수 거리이며 추적 연속성·순간이동 검사를 적용한다.
- 기존 ACC counter/hotlap timer 규칙으로 두 출발선 통과 사이만 완주로 판정한다. 종료/시간 제한을 분리하고 시간 제한은 SB3 `TimeLimit.truncated`로 다음 상태 가치를 유지한다. F8·GUI 중지·장치/통신/기록 오류는 학습하지 않는다.
- 정차 ≤1km/h가 0.5초 이상 유지되고 vJoy 해제가 확인된 뒤 경험 검증·commit·SAC 갱신·저장을 실행한다. replay 256개 미만이면 갱신을 보류한다. 갱신 횟수는 min(새 경험 수//4, 2000)이다.
- 체크포인트는 actor/critics/optimizers/replay/Python·NumPy·Torch·환경 난수와 native 난수, 경로·보정·보상 바인딩, 검증 이력을 보관한다. 새로운 native bundle의 수치 대조 후 원자적으로 완성 표시한다. 다음 회차는 저장된 bundle을 불러온다.

기존 사전학습 산출물은 출력 해시를 모두 검사하여 가져온다. 과거 빌드 실행 파일·소스의 해시는 역사적 provenance로 보존하며 현재 바이너리와 일치해야 한다고 가정하지 않는다. 현재 실행에 사용하는 모델·정규화·경로와 수치 대조 결과는 새 불변 bundle에 다시 묶는다. 기존 shadow의 과거 exporter 바이너리 변경도 현재 Rust로 보관된 parity 입력/출력을 다시 대조한 경우에만 허용한다.
